# SDL DSL Package Summary (`sdl/dsl`)

**Purpose:**

This package implements the execution engine for the System Design Language (DSL). It takes an Abstract Syntax Tree (AST), evaluates it by orchestrating calls to `sdl/core` and `sdl/components`, and produces analysis results. It aims to provide a high-level, declarative interface, abstracting direct manipulation of probabilistic outcomes.

**Target Execution Model (Model V4 - Implicit Dual Track):**

*   **Implicit Outcomes:** The DSL syntax deals with functional types (`bool`, `enum`, `int`), not `Outcomes` directly.
*   **VM Dual Track:** The VM implicitly tracks two distributions per variable/expression: `Outcomes[V]` (for discrete functional value `V`) and `Outcomes[DurationRange]` or `Outcomes[Duration]` (for latency).
*   **Discrete Values:** `V` in the value track is restricted to registered discrete types (bool, enums).
*   **Explicit Delay:** Latency is added *only* by leaf operations or explicit `delay` statements.
*   **Probabilistic Branching:** `distribute` statement handles probabilistic control flow. `if` splits based on boolean value outcomes.

**Hybrid Implementation Strategy:**

*   **Bytecode:** Use bytecode compilation for expressions and simple sequential statements for potential performance gains.
*   **VM Go Helpers:** Delegate complex probabilistic control flow (`if`, `distribute`, `switch`, `parallel`, `fanout`) to dedicated Go functions within the VM (`evalIfStmt`, etc.). These Go helpers orchestrate context splitting, recursive calls to the bytecode execution loop for branches, and result combination using `sdl/core` functions.

**Key Concepts & Components:**

1.  **Abstract Syntax Tree (AST) (`ast.go`):**
    *   Defines Go structs representing the parsed DSL (updated for Model V4 grammar). Includes nodes for declarations (`ComponentDecl`, `SystemDecl`, `EnumDecl`), statements (`LetStmt`, `IfStmt`, `DistributeStmt`, `DelayStmt`, `ReturnStmt`, `BlockStmt`), and expressions (`LiteralExpr`, `IdentifierExpr`, `CallExpr`, `MemberAccessExpr`, `BinaryExpr`, `UnaryExpr`).
    *   AST generated by `components/decl` or (future) parser.

2.  **Virtual Machine (VM) (`vm.go`, `eval_*.go`):**
    *   Core execution engine walking the AST or executing bytecode.
    *   Manages `Environment`s and an execution `stack`.
    *   **Dual Track State:** Designed to manage `VarState { ValueOutcome, LatencyOutcome }` on the stack and in the environment.
    *   **Evaluation (`Eval`):** Main dispatch function, returns `(*VarState, error)`. Specific `eval*` functions handle different AST nodes/bytecode instructions.
    *   **Composition:** Uses `combineOutcomesAndReduce` helper, which combines latency tracks (via reducer registry) and propagates value tracks ("Take Last" currently).
    *   **Control Flow:** `evalBlockStmt` manages sequence via stack. `evalIfStmt` handles conditional logic using `splitDualTrack`. (evalDistribute, evalSwitch etc. pending).
    *   **Reduction:** Uses `reduceStateIfNeeded` helper, applying configured duration reducer (`vm.durationReducer`) and value reducers (`TrimToSize*`).

3.  **Environment (`environment.go`):**
    *   Lexical scoping via nested maps storing `*VarState`.

4.  **Reducer Registry (`vm.go`):**
    *   Stores `core.ReducerFunc` primarily for combining `Outcomes[Duration]` during sequential composition. Default `Duration+Duration` adder registered.

5.  **Driver (`driver.go`):**
    *   Provides `RunDSL` to execute a system AST.
    *   Initializes VM, registers built-in components/functions.
    *   Instantiates system components.
    *   Executes `analyze` targets by calling `vm.Eval`.
    *   Calculates metrics using `core` functions and returns results in `AnalysisResultWrapper`.

6.  **Internal Functions (`driver.go`, `vm.go`):**
    *   Go functions callable by the VM (e.g., `GetDiskReadProfile`, `DurationMS`) providing bridges to component logic or VM primitives. Registered via `vm.RegisterInternalFunc`.

**Current Status:**

*   AST (`ast.go`) updated to reflect target Model V4 grammar (pending removal of deferred/unused nodes).
*   VM structure (`vm.go`) refactored for `VarState` dual-track (Environment, Stack). `Eval` signature updated. Configurable duration reducer added (`vm.durationReducer`).
*   Core evaluators implemented/updated for Model V4: Literals, Identifiers, `AndExpr`, `BlockStmt`, `AssignmentStmt`, `ExprStmt`, `ReturnStmt`, `IfStmt`, `InternalCallExpr`, `MemberAccessExpr`. **Note:** `combineOutcomesAndReduce` uses "Take Last Value" which is inaccurate for combined probabilities. `splitDualTrack` uses reflection for latency splitting pending core helpers.
*   `evalDelay`, `evalDistribute`, `evalParallel`, `evalRepeat` (parallel), `evalFanout`, `evalSwitch`, `evalFilter` are **NOT YET IMPLEMENTED**.
*   `evalCallExpr` implemented but needs component methods updated for dual-track return.
*   Bytecode compiler/interpreter is **NOT YET IMPLEMENTED** (currently direct AST evaluation).
*   Driver (`RunDSL`) works for simple systems with literal params.
